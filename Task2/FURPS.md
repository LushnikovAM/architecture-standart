| Код | Требования | Комментарий |
|-----|------------|-------------|
| F | Функциональные (Functionality) | |
| F1 | Сайт показывает новому клиенту список доступных депозитов с актуальными ставками. |  |
| F2 | Новый клиент подаёт с сайта заявку на депозит, указывая Ф. И. О. и номер телефона. Заявка появляется в системе кол-центра банка, менеджер видит её и перезванивает клиенту. | Данные необходимо защищать с помощью механизма шифрования трафика. |
| F3 | Менеджер кол-центра может зафиксировать по заявке особые условия. | |
| F4 | Новый клиент завершает идентификацию только личным визитом в отделение.  | Открыть депозит новому клиенту полностью онлайн нельзя. |
| F5 | В интернет-банке клиент видит общий каталог депозитов с актуальными ставками и персональную ставку для себя. |  |
| F6| Клиент интернет-банка подаёт заявку на открытие депозита, указывая счёт и сумму, и подтверждает операцию СМС-кодом. | Сценарий СМС-подтверждения реализует команда банка, без доработки ядра интернет-банка подрядчиком. |
| F7 | Сотрудники бэк-офиса депозитов и бэк-офиса кредитов совместно ведут ставки и согласуют ставку по заявке. | Сейчас ставка считается в XLS от ставки рефинансирования, объёма кредитов и депозитов и приходит почтой раз в день.  |
| F8 | На MVP заявку обрабатывает менеджер бэк-офиса и подтверждает условия депозита в АБС. Полностью автоматическое открытие в этот объём не входит. | Промежуточная цель — около 6 месяцев; цель на год — открытие без бэк-офиса. Контур заявки нужно отделить от учёта в АБС уже сейчас, иначе автоматизацию следующего этапа придётся встраивать в PL/SQL. |
| F9 | Клиент получает отдельное СМС после подтверждения размера ставки и отдельное СМС после открытия депозита. |  |
| U | Удобство использования (Usability) | |
| U1 | Клиентские интерфейсы сайта и интернет-банка следуют принятой дизайн-системе банка: привычные цвета и брендированные элементы. | |
| U2 | Просмотр ставок и подача заявки выполняются в мксимально удобном  интерфейсе | |
| R | Надёжность (Reliability) | |
| R1 | Сервисы приёма заявок и витрины ставок работают 24/7 с доступностью 99,9%. | |
| R2 | При отказе основного ЦОД витрина и приём заявок остаются доступны в резервном ЦОД и продолжают выдерживать нагрузку канала. | Команда интернет-банка утверждает, что эти требования пока невыполнимы. |
| P | Производительность (Performance) | |
| P1 | Отклик интерактивных операций витрины и подачи заявки находится в пределах миллисекунд и не превышает 1 секунды. |  |
| S | Поддерживаемость (Supportability) | |
| S1 | Новые компоненты опираются на уже принятые в банке СУБД — MS SQL и Oracle.  | |
| S2 | Асинхронный обмен нового контура проектируется с расчётом на Kafka, но текущая система к Kafka не подключается. |  |
| S3 | Микросервисное разбиение интернет-банка ограничено сценарием открытия депозитов. Остальной монолит, включая платежи и текущие счета, не переписывается. |  |
| S4 | Каталог ставок и правила согласования — один источник для сайта, интернет-банка и отделений. |  |
| +R | + Ограничения (Restrictions) | |
| R1 | Персональные и финансовые данные сайта и интернет-банка передаются только по зашифрованному каналу. | |
| R2 | АБС масштабируется только вертикально.  | |
